# 0.6.0 → 0.7.0 阶段 A｜本地数据库升级与退回

**这份开发构建请在独立浏览器资料或测试酒馆使用。** A 与旧版同用数据库名；在正式账号打开它就可能升级真实数据库。B 完成调度接线前，保留正式环境的 0.6.0。升级不会向模型发送请求。

## 实际修改什么

| 项目 | 0.6.0 | 阶段 A |
|---|---|---|
| IndexedDB 名 | lin-dynamic-persona-v5-<account> | 同名；沿用账号隔离 |
| 物理布局版本 | 5 | 6。此数字不是插件版本或人格格式 |
| 人格快照、备份、角色卡与设置 | 人格格式 5，原有 streams/nodes/journal 等 | 人格格式仍为 5；原 export/import/delta、v4 迁移与只读旧备份保留 |
| usage | 队列、批次、job、额度 | 保留全部旧行；新增受控事务，受管 job/batch 标签 managed:7；增加 queueScope 索引 |
| queueLedger | 无 | 新表：受理凭据、逐项状态/事件、冻结批次引用、撤销和归档凭据。按 scope、[scope,kind]、[scope,unit,ref] 检索，不保存聊天原文 |
| v6Rollback | 无 | 仅在升级已经存在的 v5 库时，保存升级前 streams/nodes/journal/usage/terms/archives 六表的原行镜像。这里是私人旧库备份，可能含原有证据和人格文本，切勿随交接包或公开日志分享 |

升级在浏览器的单个 versionchange 事务内创建表／索引，以 cursor 复制旧行，记录能观察到的旧队列成员。任何读写、约束或空间错误都会使升级整体失败；不会先清空 v5。额外空间可能接近旧六表的大小：空间不足时先保留原环境备份，不应删个人数据强行迁移。关闭同账号旧页面后重试；旧连接收 versionchange 会关闭。成功后旧代码再以版本 5 打开会被浏览器拒绝，这也阻止未打补丁的旧标签页继续写同一份新库。全新账户不创建虚构的旧快照，exportV6Rollback() 返回 null。

**迁移读取边界**：旧队列现存锚点标为 legacy，旧队列/批次中可以识别的 sourceId 只标“有历史痕迹”。sourceId 未知时不反猜聊天内容，既有已处理数组与已提交人格不回填虚构的精确派发历史。旧库在 0.6.0 阶段已经丢失且毫无痕迹的成员无法恢复。legacyUnverifiedCount 是已知历史标识数，不是“历史遗漏总数”。未登记过的历史聊天不进入 acceptedCount。第一次由新入口受理的楼和片段才有完整可核验的生命周期。

仍待处理的旧锚点可在 B 核实当前选中来源后映射、冻结与处理。旧失败批的 job 与指纹可核对时，用 adoptLegacyFailure；旧 lastJobId 虚指时保持失败历史，允许明确 archive 并保留待处理成员。迁移本身不向任何接口补发请求。

## 两条安全的退回路径

1. **首选：留着正式 0.6.0 的原浏览器资料。** 在独立测试资料升级，回退时直接回原资料即可。升级前从 0.6.0 导出人格备份；如要保留待办、失败尝试和预算，需一份完整的浏览器资料备份，不能仅依赖人格 JSON。
2. **已升级旧库：恢复一份旧环境，保留活动新库。** 本版本 `await db.exportV6Rollback()` 读取只读的升级前六表快照。由 B 或开发者在同来源、**同账号标识但全新的浏览器资料中**调用以下开发接口；它只创建空目的库，拒绝覆盖任何已有 v5/v6 数据库。先恢复，关闭开发工具，再用原版 0.6.0 打开那个新资料。不要在原库上删除表、强制降版本或删库。这一路径已在 Chromium 的第二个独立浏览器上下文用真实 IndexedDB 验证：恢复后六表可读，既有目的库拒绝再覆盖。

```js
// 在已升级的开发资料，db 为当前账户 Database 实例；这份 JSON 属于个人，请自行离线保管。
const snapshot = await db.exportV6Rollback();
// 把 snapshot 放入一个新的、尚未打开插件的测试资料；用与 0.6.0 相同的 account 和浏览器 origin。
await Database.restoreV6Rollback(account, snapshot, indexedDB);
// 返回 lin-dynamic-persona-v5-<account>；非同账户/非 v5 镜像、已有目的库或重复键均不覆盖。
```

这是**升级前时间点**的恢复。此后在 v7A 新建的人格、收发尝试和来源终态不会反向伪装成 v6 历史；不要为了回退删除活动 v7A 库。需要保存升级后的全部工作时保留原浏览器资料的完整离线备份；日常人格 export 不含 usage 和新队列账本。B 若仍沿用物理版本 6 和本合同，可在同一测试资料继续读取 A 所写的库，无需把整库转写到聊天 metadata。跨设备、隐私模式和清空站点数据都不等于自动迁移。

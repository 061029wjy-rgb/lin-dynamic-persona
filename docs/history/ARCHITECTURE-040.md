# v0.4.0 架构与功能状态

## 数据流

已保存的选中消息 → 原文分段与角色知情过滤 → 分支指纹 → 本地事件/人格库 → 中文 BM25 检索 → 一段有预算的临时系统提示。

可选分析另走异步队列：当前 ST 模型提出结构化候选 → 精确 source ID、Swipe、UTF-16 原文位置、角色、时序和分支校验 → 审核箱 → 玩家批准后投影。分析失败或切换聊天时直接丢弃，不影响主生成。

## 不采纳的原指导要求

- “引文精确存在”只能证明文本出现，不能证明对白内容客观为真，因此事件模态与人格因果仍需分开审核。
- “多条证据”不能按楼层数量机械计算；同一事件被反复讲述仍只是一项 occurrence。
- `generateRaw()` 没有可由扩展可靠传入的独立 AbortSignal。取消表示拒收迟到结果，无法保证上游已经停止计费。
- IndexedDB 不会自然跟随 ST 聊天备份跨设备，所以恢复先核对指纹，无法匹配就暂停。
- 高信任自动批准 L1 被取消为默认能力；永久人格的误写代价高，玩家审核比便利更重要。

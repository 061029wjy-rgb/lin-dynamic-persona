# Lin Dynamic Persona · 动态人格引擎

让角色根据**自己的经历**逐渐改变。原始人设是起点，剧情是证据，玩家始终拥有最后的编辑权。

独立 SillyTavern 前端扩展 · **0.1.0（首个可安装测试版）** · 中文界面 · 无运行时依赖、无构建步骤。

## 安装

SillyTavern **1.19.0 或更新版本**，进入「扩展 → 安装扩展」，粘贴：

```text
https://github.com/061029wjy-rgb/lin-dynamic-persona
```

刷新页面，在扩展设置中展开「Lin Dynamic Persona · 动态人格」。也可以解压安装 ZIP，将 `lin-dynamic-persona` 整个目录放入运行 ST 服务端的设备的 `data/<用户>/extensions/`；目录内直接应有 `manifest.json`。

不安装旧情绪插件、不安装记忆插件、不填写世界书变量或 EJS，均可使用。卸载时移除扩展目录并刷新；角色卡、世界书、预设没有任何需要恢复的修改。

## 第一次使用

1. 打开聊天，展开扩展面板。原始卡可在「原始人设（只读）」查看。
2. 点击「＋ 创建影响」，可先创建一个持续 3 次回复的即时状态。只有该角色自己的有效回复推进寿命；冻结可暂停生命周期。
3. 默认开启自动分析，使用 ST **当前连接**的 `generateRaw` 进行额外后台模型请求。模型必须能返回 JSON；解析失败会跳过这次分析，不影响聊天。可关闭自动分析或设置单独的 OpenAI 兼容接口。
4. 在「场景与剧情时间」指定当前人物、场景、关系或行为。限定范围的影响只有在对应范围匹配时注入，空范围为不限。人物名称或 avatar ID 必须与影响范围使用一致标识。
5. 旧聊天首次启用时，分析按时间顺序每批最多 12 条已知消息推进。需要一次性追赶历史，可点「重建人格」。它保留人工/冻结记录和屏蔽规则，并依次处理最多 100 批；可再次运行分析继续剩余部分。
6. 定期「导出完整备份」。人格数据库位于**当前浏览器、当前站点、当前 ST 账号**的 IndexedDB 中，不随普通聊天 JSONL 自动迁移到其他设备。

## 分层与演化

| 层级 | 用途 | 默认寿命 |
| --- | --- | --- |
| 原始人设 | 只读角色卡基线，保留明确底线 | 不由本插件修改 |
| 后天人格 | 有证据的习惯、认知、关系模式 | 持续，可形成、强化、削弱、修订、消退 |
| 短期心理 | 一段时期的戒备、疲惫、疏远等 | 自动分析 4–15 次本人回复 |
| 即时影响 | 一时的喜悦、恼怒、念头与偏差 | 自动分析 1–3 次本人回复 |
| 自主目标 | 当前角色自己的意图和事务 | 可持续或设定结束条件 |

这些不是好感度分数，也不是固定标签库。每条自动变化保存事件、逐字引用、角色的主观理解、形成理由、强度、自我认知与实际行为。模型会结合原因、原始人格、和解及反证判断，不执行“三次失约必然不信任”的固定规则。

即时状态不要求表现出来。“持续三次”可以三次都正常工作、不发脾气。过期只停止当前作用，经历保留以供之后判断；禁止沉淀的状态不会自动转成长久人格。分析旧历史时，短时状态会扣除事件之后已经发生的本人回复，不把几十轮前的情绪当成刚发生。

用户可以把寿命设为任意有限次数、永久，或手动维护的剧情分钟。自然语言结束条件由后续剧情分析判断，也可人工停用/删除；插件不从现实钟表推断“今晚结束”。

## 玩家编辑权

- 查看、创建、编辑、冻结、启用/禁用、删除所有影响；编辑默认切换为「人工管理」，自动分析不能再改写。也可显式选择「允许自动演化」。
- 每个正文节点保留最多 40 次人格修订，支持回退。聊天分支的历史快照不受这 40 次限制。
- 删除默认写入**概念与来源消息屏蔽**，阻止模型用同一条剧情换一种措辞重新创建。屏蔽以整条来源消息为单位，比只屏蔽一句话更保守。
- 可以单独删除经历；依赖它的影响会停用。可以查看并解除屏蔽规则。
- 冻结既保护内容，也暂停寿命。禁用的影响不注入、不递减，也不能被分析器改写。
- 修改过去节点的人工状态后，原有后续自动快照会失效，从修改后的共同前缀重建，防止旧后果覆盖新的人工决定。

## 分支、角色权限与恢复

每个存档有独立命名空间，每条所选正文对应 SHA-256 链式指纹。Swipe 序号、隐藏思考与 token 不构成剧情；真正的正文变化才产生不同节点。

- 新 Swipe、重新生成从共同前缀取状态，替换同一条回复只计一次。
- 续写沿用同一条回复的计数，并把仍存在的证据引用移到新正文节点。
- 编辑、删除、回档、聊天切换恢复对应前缀；不会沿用被删除的未来剧情。
- ST 官方检查点/分支复制的插件标记只用于找到共同前缀。新存档的快照独立复制，之后互不修改。
- 群聊按 `original_avatar` 识别发言者，名字不唯一时不猜测。本人消息、单聊的用户消息默认可用于分析；群聊中他人消息需在「角色知情授权」逐条开放。取消授权会移除相关记录。
- 检索先验证当前分支和角色权限，再做关键词/向量排名。不会先搜全库再让模型自觉过滤。

官方源码没有一个可依赖的统一“快速恢复”事件。本扩展监听 `CHAT_CHANGED`、`CHAT_LOADED` 等实际事件，并在生成前检查正文一致性。恢复不匹配时可以选择恢复匹配状态、重建、停用此存档或取消。**取消只暂停人格注入，不撤销 ST 已经完成的聊天恢复。** 关闭弹窗后自动采用当前正文的完全匹配快照或最近共同前缀，绝不采用未来状态。

## 向量检索（可选）

设置完整 Embedding URL，例如 `https://你的服务/v1/embeddings`，填写模型并启用。接口需要允许浏览器跨域访问；不支持的服务可通过自己控制的兼容网关使用。API Key 只留在当前页面内存，刷新后重新填写，不进入设置、备份或仓库。

语义检索在后台运行，索引按存档、人物、模型、正文分隔；更换模型不会混用维度。每批最多补齐 24 条经历向量。前台生成只使用当前合法经历、关键词和已经准备好的同分支语义结果；新话题在后台向量尚未完成时使用关键词与时间排序。没有 Embedding、超时、错误或维度不一致时安全降级。点击「重建向量索引」清理可再生缓存并重建一批，后续查询继续填充。

## 旧情绪插件

已审阅 [`061029wjy-rgb/lin-emotional-control`](https://github.com/061029wjy-rgb/lin-emotional-control) v1.2.0。该版本自行抽签并在最终请求阶段插入提示，没有公开的状态交换接口，因此本插件不冒充已经同步了它的私有手记。

默认「协作」：识别旧插件的运行标记及 `human_temper_v1.enabled`；旧插件管理即时情绪/自主落点，本插件不重复注入自身的即时层、目标层和演出抽样，保留后天人格与短期心理。

选择「完全接管」时，先在旧插件里停用它；检测到旧插件仍运行时，本插件跳过注入并提示，避免两个引擎争夺控制。也可选择检测到旧插件就完全暂停本插件注入。不会改写旧插件设置。

本插件自己的演出控制保留情绪烈度、阴暗面权重、行为随机性、自主目标、生活插曲和跨回合情绪。同一角色同一正文节点的插曲选择是确定的，不因重复调用重复抽签；抽中的方向不作为已发生事件存入长期人格。

## 存储与兼容边界

人格、经历、屏蔽、修订和向量只写本扩展的 IndexedDB。ST 设置只保存本扩展开关/配置和账号隔离 ID；聊天元数据只保存版本、存档 ID、所有者与正文指纹，不写人格正文。

备份导入到新的独立命名空间，不覆盖正在使用的存档。导入后选择「采用备份快照」，仅允许正文指纹完全匹配的状态。跨设备需要同时迁移聊天和插件 JSON 备份。清除浏览器站点数据会删除本地人格数据库。

生成前使用 `setExtensionPrompt` 一个固定槽位，位置为故事/系统区域，关闭世界书扫描，受 token 预算限制。插件不修改请求 JSON、采样参数、输出长度、Vertex Gemini 参数、预填充、思维链、消息正文或原角色卡。生成前本地准备超时就跳过本轮，后台分析结果过期则丢弃。

`generateRaw` 是 ST 官方独立请求，但其当前接口不接受外部 AbortSignal：切换聊天/开始新回复后，旧请求可能仍在服务端完成，本插件保证不接纳过期结果、不继续发下一批；单独 API 模式支持主动取消。ST 当前 `saveChat()` 不返回可靠的服务端保存确认且会吞掉部分错误，因此本插件依据最终渲染的有效正文确认选定回复，再保存对应本地快照；无法承诺网络断线时 ST 服务端一定已经落盘。

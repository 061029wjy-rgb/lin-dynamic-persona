# Lin Dynamic Persona

面向 SillyTavern 的动态人格扩展，让角色的心理状态能够随经历变化，同时保留自己的判断、目标和生活。

插件依据角色实际可知的聊天原文，记录即时感受、短期心理、长期倾向与目标，并将适用内容注入后续生成。人物状态按角色、存档和分支分别保存。

本版本包含完整前端、可选 gateway 源码、测试和开发文档：

## 主要功能

### 手动管理人物状态

可以创建、编辑、启停、冻结和删除人物影响，调整角色的感受、心理倾向与目标。关闭额外模型请求后，仍可使用本地管理功能。

状态保存在插件自己的本地数据库中，不改写角色卡、世界书、预设或聊天正文。

### 根据经历分析变化

分析仅使用当前角色获准知晓的原文和必要上下文，并核验引用出处与人物归因。

支持三种处理方式：

- **手工审阅**：分析建议进入待审列表，由玩家决定。
- **保守采用**：符合规则的低风险变化可以自动采用，长期变化留待审核。
- **自动成长**：明确启用后，允许通过证据与基线检查的长期变化自动采用。

合法的空分析结果只表示本批没有可信的新变化，不会为了生成结果而强行新增人格条目。

### 角色与分支隔离

人物状态结合当前存档、角色和聊天分支使用。遇到编辑、删除、切换分支或切换聊天时，会重新核对来源；过时分析不能直接写入当前状态。

### 情绪演出与自主性

保留情绪、行为变化和随机事件相关控制，也可只启用人格成长功能。

与 `lin-emotional-control` 共存时，可由旧插件负责随机演出，本插件负责人格状态，避免重复承担同一功能。

### 本地文字检索

使用本地文字索引检索相关内容，无需额外配置向量或 Embedding 服务。

## 分析请求与预算

额外模型请求默认关闭，需要主动启用。

可以沿用酒馆当前模型，也可以配置独立分析接口。连接测试、沙盒、第二意见和每批分析分别计为独立请求，可能产生供应商费用。

支持账户、日期、会话、配置档及角色相关限额。面板区分：

- 尚未派发的额度预留；
- 已登记的派发意图；
- 未派发且已退还的预留；
- 未采用或结果未知、可能已计费的尝试；
- 供应商报告的用量与本地估算。

本地派发记录不能证明供应商是否实际收单或收费。

## 队列与失败处理

### 完整登记，分批处理

先登记每个待分析楼层的完整可见来源，再选择本批实际发送的片段。

一楼只分析了一部分时，其余片段继续保留；分析期间新增的楼层也不会被旧快照覆盖。

### 成功提交后才确认完成

人格变化、已处理来源、请求记录与队列确认在同一事务中提交。事务失败不会留下半份新人格，也不会提前移除待办。

### 不自动重发结果未知的请求

断网、超时、取消或切换聊天后，已经登记派发的尝试会保留待核实状态，不自动重新发送。只有确认尚未派发的预留才能退还额度。

### 显式重试原批次

重试会核对原冻结来源、完整楼层映射、配置、模型及请求指纹。后续新剧情不会混入原失败批次。

如果来源或请求条件已经改变，需要明确归档并重新建立待办。归档重建本身不会立即发送新请求。

## Inspector 与诊断

“分析预算与日志”面板可以查看：

- 当前队列状态与待办数量；
- 额度占用、用量和费用口径；
- 失败批次及其派发记录；
- 已受理来源的账本核验；
- 失踪来源、孤立批次、来源不符和历史未核实记录；
- 注入诊断及脱敏样本。

旧版留下但无法充分证明的历史会单独标记，不会被当作完整、已核实的记录。

## 安装与开始使用

当前构建请使用独立测试酒馆或独立浏览器资料。升级前保留原插件及完整浏览器资料备份；普通人格 JSON 不包含完整队列、失败尝试和预算记录。

1. 解压完整源码包。
2. 将 `lin-dynamic-persona` 文件夹放入测试环境的扩展目录。
3. 确保 `manifest.json`、`index.js` 和 `src/` 直接位于该文件夹内，避免重复嵌套同名目录。
4. 刷新酒馆，在扩展设置中打开 Lin Dynamic Persona。
5. 先核对当前聊天与本地状态，再按需要启用额外分析和自动排队。

普通前端使用无需运行 npm。需要服务端管理密钥或 Vertex ADC 时，再查看包内 gateway 文档。

Manifest 声明最低客户端版本为 SillyTavern 1.19.0；实际宿主、设备及接口兼容性仍需对应环境验收。
